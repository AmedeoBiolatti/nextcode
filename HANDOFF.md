- Word wrap and code folding (user request: last part of everyday editing), in `crates/ui/src/editor/`:
  - `display_map.rs`: `DisplayMap` (one per editor view) maps buffer lines to screen rows. Wrapping is in columns (`char_width`: `unicode-width`, tabs 1 since they render as one space; the editor font is monospaced), so it needs no shaping: `wrap_line` (greedy; breaks after whitespace and around wide chars, long words anywhere, whitespace hangs past the edge, continuation indent = the line's indentation unless that exceeds half the width) feeds `line_rows` (rows per line, counted for every line when the width changes, then only for lines an edit touches: `edit` splices placeholders per `Change` and recounts them). `row_starts` is the prefix sum over lines (hidden lines contribute 0), rebuilt after edits/fold changes (integer adds); without wrap and folds nothing is stored (rows = lines). API: `row_count`, `line_row`, `row_line`, `rows(first, count)` (visible `DisplayRow { line, range, indent, first, last }`, breaks computed per visible line), `row_of`/`point` (offset → row, screen column), `offset_at(row, column)` (off the end of a continuing row it stays before the row's last char, so a cursor never sits ambiguously at a wrap point), `row_end`, `shown_line`, `is_hidden`, `clip(offset, bias)`. A cursor at a wrap position draws at the start of the next row (`DisplayRow::shows`).
  - Folds (`display_map::Fold { header, start, end }`: header line start, header line end, end of the last hidden line) live in the `DisplayMap`, so panes fold independently. `Fold::map` moves them through each `Change`; an edit overlapping the hidden text, replacing the header line, or splitting it at its end drops the fold, as does anything that no longer delimits whole lines. `Editor::reveal_selections` (from `set_selections`, `finish_change_with`, `set_cursor`, go-to-line preview, `restore_state`) opens folds hiding a cursor or one end of a selection that does not cover the fold; `move_selections` clips heads with `clip` so motions step over folds instead (Right from a header end goes to the line after the fold).
  - Editor: `layout` shapes only the visible rows (each row is its own `ShapedLine`, offset by its continuation indent; highlights are queried per run of consecutive shown lines so folded text is never highlighted) into `RowLayout`s (`number`/`mark` on a line's first row, `chevron`, `folded` = the `⋯` after a folded header). Hit-testing (`offset_for_position`, `line_column_at`, `character_at`), IME `bounds_for_range`, hover (`HoverPopover::row`) and completion anchoring (`screen_position`) use the rows; vertical motion, Page Up/Down, autoscroll, centering and `scroll_line` use display rows; `Selection::goal` is now a screen column. Home/End go to the row start/end first on wrapped lines. `Selection::at_row_end` (cursor affinity): a head at a wrap position is drawn at the end of the upper row instead of the next row's start; set by End, clicks/drags past a row's end (`cursor_for_position`) and vertical motion landing there (`DisplayMap::offset_at` returns it), read by `DisplayMap::row_of`/`point`/`DisplayRow::shows`, cleared by every edit and other motion. Wrap forces `scroll.x = 0`. Column selection (Shift+Alt/middle drag) counts buffer columns and skips hidden lines; Add Cursor Above/Below skip hidden lines.
  - Word wrap: `ToggleWordWrap` (`Alt+Z`, View > Word Wrap) sets the view's `word_wrap: Option<bool>`; otherwise `theme::word_wrap(language)` (settings `"word_wrap"` plus `languages.<id>.word_wrap`, Markdown on by default; a bit mask refreshed in `theme::refresh`, applied live). Flow control: a credit window (`TUNNEL_WINDOW` = 1 MiB) per tunnel and direction, granted back with `ClientMessage::Credit` / `Event::TunnelCredit` as bytes are delivered, so neither side's frame reader ever blocks on a slow socket (no head-of-line blocking; a stalled download holds at most the window). The install name contains the protocol, so WSL/container agents are reinstalled automatically.
