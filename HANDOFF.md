  - `brackets.rs`: `Syntax::bracket_partner` walks the bracket token's siblings in the tree (brackets inside strings/comments are not tokens, so they never match); where the tree has no token there (Markdown prose, plain text) a text scan within 64 KiB skips string/comment highlight spans. - Split editor and session restore (user request: everyday-editing parity): `crates/ui/src/workspace/panes.rs` holds `Pane` (tabs + active), `PaneNode` (binary tree of `Split { axis, ratio, first, second }`; `Workspace::panes` is kept in leaf order, which `Ctrl+1/2/3` and next/previous follow), the pane actions (`SplitRight` `Ctrl+\`, `SplitDown` `Ctrl+K Ctrl+\`, `FocusFirst/Second/ThirdPane` `Ctrl+1/2/3` (one past the last splits right, as VS Code), `FocusNext/PreviousPane` `Ctrl+K Ctrl+Right/Left`, `MoveTabToNext/PreviousPane` `Ctrl+Alt+Right/Left` (splits a pane off at the edge; this replaced the JetBrains Back/Forward duplicates on those keys), `ClosePane` `Ctrl+K W`), tab drag and drop (`DraggedTab` by view entity id; tab bar = insert/append, pane middle = move, outer quarters = split that side), split handles (bounds recorded by a `canvas` per split, dragged through the workspace's `on_resize_move`), and rendering.   - LSP: one view per file holds the server document (`Tab::lsp_owner`); it moves to the view that gets focus (`take_server`/`adopt_server`, same URI and version, no didClose/didOpen) and to a remaining view when the owner closes. Unsaved edits are not kept. Unit tests keep project state in a per-thread temp dir (`layout::state_root` under `cfg(test)`), removed by the tests.
